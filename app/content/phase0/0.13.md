## Why this matters

Every driver, on every chip, ends in a write to a memory address. `gpio_set_level()` is a convenience; underneath is one store instruction. Engineers who have done it by hand once can read any vendor’s code, debug with a register dump, and move to an STM32 without fear.

## Prerequisites, hardware, time

An LED and resistor on GPIO4 of an S3 board (or the ESP32-CAM, whose flash LED is on GPIO4: bright, do not look into it). Lessons 0.4 and 0.11. The ESP32-S3 Technical Reference Manual. 75 minutes.

## How it works

**Memory-mapped I/O.** The CPU has one address space. Some addresses lead to RAM, some to flash, and some to peripheral registers: storage whose bits are wired to hardware. Writing a 1 to the right bit at the right address raises a pin’s voltage. Reading an address can return a pin’s level, a counter’s value or a received byte. To the CPU it is all loads and stores.

**What `REG_WRITE` is.** In essence, a macro that casts a number to a pointer and stores through it:

```c
#define REG_WRITE(addr, val)  (*(volatile uint32_t *)(addr) = (val))
```

`volatile` tells the compiler that this location can change by itself and that every access matters, so it must not optimise any away. Lesson 1.3 returns to it.

**Why set and clear registers exist.** `OUT |= mask` is read, modify, write. If an interrupt changes the register between your read and your write, its change is lost. `W1TS` and `W1TC` (“write one to set”, “write one to clear”) change only the bits you name in a single store, so nothing can come between.

**What the driver was doing for you.** `gpio_set_direction` sets the pin’s bit in the enable register. `gpio_reset_pin` also selects the GPIO function for that pin in the IO MUX, because a pin can belong to several peripherals. The lab keeps those two calls and replaces only the loop; the stretch goal replaces the direction too.

**The same idea on another chip.** The classic ESP32 has registers with the same names at different addresses. An STM32 calls them `ODR`, `BSRR` and `MODER`. The names change; the three ideas (output value, atomic set and clear, direction) do not.

## When to use it, when not to

| Situation | Use |
| --- | --- |
| Application code | The driver. It is portable, checked and thread-safe |
| The tightest loop of a bit-banged protocol | Direct register writes, once measured to matter |
| Understanding or debugging a peripheral | Read the registers, in code or from the debugger |
| A peripheral the driver does not cover | Registers, wrapped in your own small HAL |

## Common mistakes and interview angles

- **Writing the whole register to change one pin.** It works on the bench with one LED and breaks the product.
- **Forgetting the direction or the function select.** The value is right and the pin does nothing.
- **Interview angle.** “What happens when you call `gpio_set_level`?” Walk down the layers: driver function, register macro, store to a memory-mapped address, a latch, an output transistor, the pin.
