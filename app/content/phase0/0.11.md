## Why this matters

Registers are bits. Protocol frames are bits. Half of all firmware bugs are a wrong mask, a wrong shift or a byte order mismatch, and almost every embedded interview opens with one of these on a whiteboard.

## Prerequisites, hardware, time

A C compiler on your computer (gcc or clang). No board. 60 minutes.

## Build it first

Use the playground until each of these takes you under ten seconds. Predict first, then click.

::widget bits

- [ ] Start from 0. Set bits 0, 3 and 7. What is the value in hex?
- [ ] Clear bit 3 without touching the others. Which operation and mask did it use?
- [ ] Enter `0xFF`. What is the low byte as a signed 8-bit number?
- [ ] Enter `0x12345678`. In what order do the bytes sit in memory on your ESP32?
- [ ] Shift `0x80000000` left by one. Where did the bit go?

Then the same in C, on your computer:

```c
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint32_t reg = 0;
    reg |=  (1u << 3);                 /* set bit 3            */
    reg |=  (1u << 7) | (1u << 0);     /* set bits 7 and 0     */
    reg &= ~(1u << 3);                 /* clear bit 3          */
    reg ^=  (1u << 0);                 /* toggle bit 0         */
    printf("0x%02X  bit7=%u\n", (unsigned)reg, (unsigned)((reg >> 7) & 1u));
    return 0;
}
```

```expected
0x80  bit7=1
```

## How it works

**Hexadecimal** is shorthand for binary: one hex digit is exactly four bits. `0xA5` is `1010 0101`. Registers are written in hex because you can see the bits through it.

**The four operations.** OR with a mask sets bits. AND with the inverted mask clears them. XOR toggles. Shift-and-AND reads one out. Everything else is a combination.

**Fields.** Registers often pack several small numbers into one word. To write a 3-bit field at bits 6 to 4:

```c
#define MODE_SHIFT  4
#define MODE_MASK   (0x7u << MODE_SHIFT)
reg = (reg & ~MODE_MASK) | ((value << MODE_SHIFT) & MODE_MASK);
```

Clear the field, then OR in the new value. Forgetting the clear is the classic bug: it works until the new value has a 0 where the old one had a 1.

**Two’s complement.** Signed integers store negative numbers so that ordinary addition works: invert the bits and add one. In eight bits, −1 is `0xFF` and −128 is `0x80`. The top bit tells you the sign, which is why reading a sensor’s signed 16-bit register into an unsigned variable gives 65,000 instead of −500.

**Endianness.** A 32-bit value occupies four bytes; which comes first is a convention. Your ESP32, and nearly every modern microcontroller, is little-endian: least significant byte at the lowest address. Many sensors and all network protocols send the most significant byte first. Joining two bytes from a sensor is therefore always explicit:

```c
int16_t accel_x = (int16_t)((uint16_t)buf[0] << 8 | buf[1]);   /* big-endian on the wire */
```

- [ ] Write `set_field(reg, shift, width, value)` and test it against five cases you worked by hand.

## When to use it, when not to

| Task | Idiom |
| --- | --- |
| One flag | `reg |= BIT`, `reg &= ~BIT`, `if (reg & BIT)` |
| A multi-bit field | Mask and shift, as above |
| Bytes from a wire into a number | Explicit shifts, never a pointer cast |
| Describing a register layout | Masks and shifts, not C bitfields: their layout is up to the compiler (lesson 1.4) |

## Common mistakes and interview angles

- **`==` binds tighter than `&`.** Always parenthesise the mask test.
- **Shifting into or past the sign bit of a signed type.** Use unsigned constants.
- **Assuming byte order.** State it in a comment next to every multi-byte read.
- **Interview angle.** “Set bit 5, clear bit 3, toggle bit 0 of this register without disturbing the rest.” Say the idiom aloud as you write it.
