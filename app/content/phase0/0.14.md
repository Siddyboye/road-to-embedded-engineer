## Why this matters

A driver call is a promise that something happens in silicon. Until you know what it is, you cannot predict what the call costs, whether it is safe in an interrupt, why a pin reads 0, or what breaks when two pieces of code share a pin. This lesson takes one small, real program, an ultrasonic ranger with an RGB LED, and follows every call in it down to the register it touches. From here on, every lesson ends its “How it works” with an **Under the hood** table for each new call, and the [under-the-hood cheatsheet](#sheets-under-the-hood) collects them.

## Prerequisites, hardware, time

- An HC-SR04 or HY-SRF05 with the 1 kΩ over 2 kΩ divider on ECHO (lesson 0.5), a common-anode RGB LED with three resistors, an S3 board

- The ESP-IDF source on your disk. With PlatformIO it is in `~/.platformio/packages/framework-espidf/` (on Windows, `%USERPROFILE%\.platformio\packages\framework-espidf\`)

## How it works

**The layers.** Every ESP-IDF driver call goes down the same stack. Open each file once and you can do it for any call in the course:

| Layer | Example for `gpio_set_level` | Where in ESP-IDF v6.1 |
| --- | --- | --- |
| Your code | `gpio_set_level(TRIG_GPIO, 1)` | `main/main.c` |
| Driver: argument checks, locks, bookkeeping | checks the pin can output | `components/esp_driver_gpio/src/gpio.c` |
| HAL: chip-independent macro | `gpio_hal_set_level(hal, n, 1)` | `components/esp_hal_gpio/include/hal/gpio_hal.h` |
| LL (low level): one chip, `static inline` | `hw->out_w1ts = 1 << n` | `components/esp_hal_gpio/esp32s3/include/hal/gpio_ll.h` |
| Register struct and addresses | `GPIO.out_w1ts` at `GPIO_OUT_W1TS_REG` | `components/soc/esp32s3/register/soc/gpio_reg.h` |
| Silicon | the bit that drives the pad | Technical Reference Manual, “IO MUX and GPIO Matrix” |

In VS Code with PlatformIO, F12 (Go to Definition) on a call walks down this stack. The LL functions are `static inline`, so after optimisation `gpio_set_level` costs a check and one store, the same store you wrote by hand in lesson 0.13.

**Under the hood: the ranger, call by call.** Every row was read in the ESP-IDF v6.1 source.

| Call | What it does underneath | Blocks? | In an ISR? |
| --- | --- | --- | --- |
| `app_main()` | Not the start of the program. `main_task` in `freertos/app_startup.c` calls it after the scheduler is running. That task has priority 1 and a stack of `CONFIG_ESP_MAIN_TASK_STACK_SIZE` (3584 bytes by default); if `app_main` returns, the task deletes itself | n/a | n/a |
| `gpio_reset_pin(n)` | Disables the pin’s interrupt, turns the **pull-up on**, pull-down off, input and output off, releases any RTC IO use, selects the GPIO function in the IO MUX and drops the pin’s reservation | No | No |
| `gpio_set_direction(n, GPIO_MODE_OUTPUT)` | Turns the input path off (`FUN_IE` = 0), routes the plain GPIO output signal (256) through the GPIO matrix, sets the pin’s bit in `GPIO_ENABLE` through the W1TS register, selects the GPIO function, disables open-drain | No | No |
| `gpio_set_direction(n, GPIO_MODE_INPUT)` | Sets `FUN_IE` in the pin’s IO MUX register, clears its `GPIO_ENABLE` bit, selects the GPIO function | No | No |
| `gpio_set_pull_mode(n, GPIO_PULLDOWN_ONLY)` | Sets `FUN_PD` and clears `FUN_PU` in the pin’s IO MUX register: a weak internal resistor, tens of kΩ (the datasheet gives the figure) | No | No |
| `gpio_set_level(n, v)` | One store: `1 << n` into `GPIO_OUT_W1TS` (high) or `GPIO_OUT_W1TC` (low). Pins 32 and up use the `OUT1` pair | No | Yes |
| `gpio_get_level(n)` | One load: bit n of `GPIO_IN`. With the input path off, as on an output-only pin, it reads 0 | No | Yes |
| `esp_rom_delay_us(us)` | Linked to `ets_delay_us`, a routine in the chip’s mask ROM (`esp32s3.rom.api.ld`). It spins on the CPU’s cycle count, so it depends on the CPU-frequency value being current. Interrupts stay on: an interrupt during the wait makes it longer, never shorter | Spins | Yes |
| `esp_timer_get_time()` | Asks the SYSTIMER peripheral to snapshot its 64-bit counter, waits for “value valid”, reads the low half, the high half and the low half again until they agree, then divides by 16: the S3’s SYSTIMER runs at 16 MHz (40 MHz crystal ÷ 2.5). Placed in IRAM | No | Yes |
| `ledc_timer_config(&t)` | With `LEDC_AUTO_CLK`, tries the APB, XTAL and RC_FAST clocks in turn and keeps the first that can make the frequency; computes a divider with 8 fractional bits and writes it to the timer. 80 MHz ÷ (5 kHz × 256 steps) = 62.5 | No | No |
| `ledc_channel_config(&c)` | Reserves the pin (logs a warning if something else already has it), routes the LEDC channel’s output signal through the GPIO matrix to the pin, with `output_invert` applied **in the matrix**, then sets the initial duty | No | No |
| `ledc_set_duty(m, ch, d)` | In a critical section, writes `d << 4` to the channel’s duty register (the low 4 bits are a fraction). The output does **not** change yet | No | No |
| `ledc_update_duty(m, ch)` | Sets `duty_start` and the low-speed `update` bit, so the new duty is latched at the start of the next PWM period | No | Yes |
| `vTaskDelay(t)` | Moves the task to the delayed list for t ticks and yields. `vTaskDelay(0)` is only a yield | Yes | No |
| `pdMS_TO_TICKS(ms)` | A macro, not a function: `ms * configTICK_RATE_HZ / 1000` in integer arithmetic. At the default 100 Hz, 60 ms is 6 ticks and 5 ms is 0 | n/a | n/a |
| `ESP_ERROR_CHECK(x)` | Evaluates x; on anything but `ESP_OK` prints the error name, file, line and expression, then aborts. If assertions are disabled in menuconfig (`NDEBUG`), it evaluates x and **checks nothing** | n/a | n/a |
| `printf(...)` | The C library formats into stdout’s buffer; a newline (stdout is line-buffered) pushes the line to the console driver, which may wait for the host. Never inside a timing window | May wait | No |

“In an ISR? Yes” means the call takes no lock that can block. An interrupt registered with `ESP_INTR_FLAG_IRAM`, which keeps running while flash is being written, may call only code in IRAM: `esp_timer_get_time` always is; `gpio_set_level` and `gpio_get_level` only with `CONFIG_GPIO_CTRL_FUNC_IN_IRAM`; `ledc_update_duty` only with `CONFIG_LEDC_CTRL_FUNC_IN_IRAM`. Both options are off by default. Lesson 2.2 returns to this.

**What the table tells you about the ranger.**

- Measuring with `esp_timer_get_time()` in a polling loop gives 1 µs steps, but any interrupt or higher-priority task that runs between the edge and your next `gpio_get_level` adds its time to the reading. At 58 µs per centimetre a 20 µs interruption is 3 mm. Lesson 2.5 latches the edge in hardware instead.
- Three `ledc_set_duty` and `ledc_update_duty` pairs change the colour one channel at a time. Each takes effect at its channel’s next period, 200 µs at 5 kHz: invisible here, important for motor drives.
- `output_invert` costs nothing: the inversion is a wire in the GPIO matrix, not code.

## When to use it, when not to

| You need | Use | Not |
| --- | --- | --- |
| To know what a call costs or whether an ISR may call it | This table, then the source | The function name |
| A pulse width to a few microseconds, occasionally | Polling with `esp_timer_get_time` and a timeout | A loop with no timeout |
| A pulse width every time, under load | A capture peripheral (lesson 2.5) | Polling |
| A short, exact delay inside a protocol | `esp_rom_delay_us` | `vTaskDelay`, whose unit is a 10 ms tick |
| A long wait | `vTaskDelay` | `esp_rom_delay_us`, which burns the CPU |

## Common mistakes and interview angles

- **A print inside a measurement.** Formatting and output take time the measurement then includes.
- **A pin reads 0 although it is driven high.** Output-only pins have their input path off.
- **Trusting `ESP_ERROR_CHECK` to protect a release build.** It can be compiled out. Handle errors you expect.
- **Unused helper functions.** A `static` function that is never called is a warning, and with warnings as errors a failed build. Delete it or use it.
- **C++ files.** In `main.cpp`, `app_main` needs `extern "C"` so the startup code can find it; in a `.c` file it does not, and `<cstdint>` becomes `<stdint.h>`.
- **Interview angle.** “What happens when you call `gpio_set_level`?” Walk the layers: argument check, HAL macro, LL inline function, one store to the write-1-to-set register, and why that register exists (no read-modify-write race).
