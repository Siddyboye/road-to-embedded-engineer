## Why this matters

Timing is the part of embedded work with no equivalent in ordinary software. A PWM frequency, a baud rate, a sensor timeout and a missed deadline are all the same question: how does a number in a register become an exact interval, and how exact is it really?

## How it works

**Clock.** A crystal vibrates at a fixed frequency; an oscillator circuit turns that into a square wave. *Period* is the time for one cycle and *frequency* is cycles per second: one is the reciprocal of the other. 80 MHz is 12.5 ns per cycle.

**PLL and clock tree.** The crystal on your board is slow, 40 MHz. A phase-locked loop multiplies it up, and dividers feed different speeds to the CPU and to each peripheral. That tree is why a peripheral’s documentation always says which clock it counts: the answer changes the arithmetic.

**Timer, prescaler, counter.** A timer is a counter driven by a clock. The prescaler divides the clock first, so the counter can measure long intervals. The counter wraps at a period value, and a comparator fires or flips an output when the count matches a number you chose. That is all a timer is, and the lab above is all three parts.

**Duty cycle.** The fraction of each period the output spends high. An LED at 25% duty looks dimmer, a motor turns slower, a servo reads the pulse width as an angle.

**Jitter.** The variation in an interval that should be constant. It has two sources: the clock itself, which is tiny, and your software, which is not. Compare the three ways of waiting:

::widget jitter

**Setup and hold time.** A receiver reads a data line on a clock edge. The data must be stable for a short time before the edge (setup) and after it (hold), or the value read is unpredictable. Every timing table in Phase 3 is a list of setup and hold requirements; jitter eats the margin.

## When to use it, when not to

| Need | Use | Why |
| --- | --- | --- |
| A waveform: PWM, a clock for another chip | A timer peripheral’s output pin | No software in the loop at all |
| Run code at an exact rate | Hardware timer interrupt | Jitter is the interrupt latency |
| Wait “about 100 ms” | `vTaskDelay` | Costs nothing; other tasks run |
| A few microseconds inside a protocol | Busy-wait | Too short for anything else; keep it short |

## Common mistakes and interview angles

- **Off-by-one in the period.** Many timers count from 0 to N inclusive, giving N + 1 ticks. Check the reference manual.
- **Assuming the peripheral clock is the CPU clock.** It often is not.
- **Interview angle.** “Generate a 1 kHz, 30% duty signal from an 80 MHz clock” is a direct test of this lesson. State the formula, then the numbers.
